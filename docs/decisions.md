## D-003 abstention 用 `_abs` 后缀识别，不看 `question_type`

**日期**：2026-11-06
**状态**：已执行（曾判断错误）

**问题**：怎么从数据里找出「无答案」题。

**我一开始判断错了**：以为这 500 题里没有 abstention 类型，因为按
`question_type` 统计只有 6 类，没有 abstention。据此写进了结论。

**实测推翻**：`question_id` 带 `_abs` 后缀的题有 **30 道**，分散在 4 个
`question_type` 里：

```
multi-session         12
single-session-user    6
temporal-reasoning     6
knowledge-update       6
```

**选择**：`is_abstention = question_id.endswith("_abs")`。

**教训**：`question_type` 是「问法」的分类，abstention 是「有没有答案」的属性，
两者正交。用一个字段去筛另一个维度，会静默漏掉整类样本——和这个项目要解决的
「静默失败」是同一种错误。

## D-004 零依赖，直到某个依赖能提升一个具体数字

**日期**：2026-11-06
**状态**：执行中

**问题**：要不要一上来就引入 jieba / numpy / 向量库。

**理由**：Stage 0 的目的是测量。每加一个库，就多一个可能掩盖真实结果的变量。
而且 baseline 的价值在于「没人需要信任它」——BM25 是 1994 年的算法，实现错了
很容易被发现。

**选择**：`dependencies = []`。BM25 手写，中文用字符 bigram。

**解除条件**：某个 benchmark 数字显示「加 X 能提升 Y」，那时再加，并在本文档记一条。

## D-005 中文用字符 bigram，不做词典分词

**日期**：2026-11-06
**状态**：待验证（当前无中文评测集）

**问题**：中文没有空格，怎么切词。

**选项**
1. jieba（词典 + HMM，~20MB 词典，纯 Python 慢）
2. 字符 bigram（无词典，O(n)）
3. 引入向量模型（重）

**理由支持 bigram**：
- 永远不会对汉字返回 0 个 token——这正是我们要避免的失败模式
- 无词典意味着没有「未登录词」问题，专有名词（`覆巢演出`、`角色管理页`）不会被切错
- 代价是索引膨胀（n 个字 → n-1 个 bigram）和精度损失

**已实现的降噪**：bigram 里含虚字占比过半就丢弃，但**不逐字符切分**。
`社会` / `会议` / `用户` 能活下来，`的了` / `是在` 被丢掉。
这个取舍来自 neural-memory 那一轮的教训：逐字符切停用字摧毁了 36/49 个常见词。

**待验证**：没有中文 benchmark，所以「bigram 够不够好」目前无法量化。
这是 D-006 的直接后果。

## D-007 检索本身不是瓶颈

**日期**：2026-11-06
**状态**：已实测

**问题**：一开始的假设是「检索是难点，所以要自建」。

**实测（BM25，零依赖，470 道可答题，排除 30 道 abstention）**

```
hit@1    0.866
hit@5    0.9511
hit@10   0.966
recall@10 0.9087
mrr      0.899
完全未命中  16 / 470
```

按类型：

| question_type | n | hit@10 | mrr |
|---|---|---|---|
| knowledge-update | 72 | 1.000 | 0.9769 |
| single-session-assistant | 56 | 1.000 | 1.0000 |
| single-session-user | 64 | 1.000 | 0.9701 |
| multi-session | 121 | 0.975 | 0.8973 |
| temporal-reasoning | 127 | 0.945 | 0.8786 |
| single-session-preference | 30 | 0.800 | 0.4656 |

**结论**：30 年前的算法 + 零依赖，在真实 haystack（平均 493 轮/题）上拿到 96.6%
hit@10。**「检索难」这个前提是错的。**

**这推翻了自建的一条主要理由。** 剩下 16 个未命中里，`single-session-preference`
（mrr 0.47）明显最弱——它要的不是「找到包含关键词的会话」，而是「推断用户偏好」。
那是理解问题，不是检索问题。

## D-008 分数不能当拒答信号

**日期**：2026-11-06
**状态**：已实测，假设否定

**问题**：如果检索器的 top-1 分数能区分「有答案」和「没答案」，拒答就可以用一个
阈值实现，Stage 1 会非常便宜。

**实测（BM25 top-1 原始分，500 题）**

```
abstention n=30   min= 9.61  median=19.67  max= 43.38
answerable n=470  min= 9.35  median=25.23  max=135.49
```

**两个分布几乎完全重叠。** abstention 题的分数能达到 43，比一半以上的正常题还高。

原因不神秘：每道 abstention 题都带一个诱饵——问仓鼠但只提过猫，问韩国但只提过
日本。诱饵和问题共享大量词汇，BM25 自然给高分。

阈值扫描（完整曲线在 `bench/results/abstention-probe.json`）：

| 阈值 | 拒答率 | 可答保留率 | 平衡 |
|---|---|---|---|
| 0 | 0.000 | 1.000 | 0.500 |
| 18 | 0.467 | 0.736 | 0.601 |
| **24** | **0.833** | **0.543** | **0.688** |
| 44 | 1.000 | 0.157 | 0.579 |

最佳平衡 **0.688**，随机基线是 0.5。而达到它的代价是**丢掉 46% 的正常查询**。

**结论**：用分数阈值做拒答不可行。这不是调参问题，是信号本身不存在。

**对 Stage 1 的直接影响**：拒答必须建模「问题与内容的关系」——这条记忆是否
**回答了**这个问题，而不只是**包含了**相关词。这是理解任务，不是排序任务。

**这是本次调研最有价值的产出。** Stage 1 的第一件事因此确定了，且有了量化的
靶子：在可答保留率 ≥0.95 的前提下把拒答率提上去。
